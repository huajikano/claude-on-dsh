# 开发文档

> 用户只填写第一部分，在【用户填写】后直接写文字。目标、功能、已有资源为必填；没有资源可写“无”或“请 Claude 调研推荐”。其他项可留空。
> 项目目录由插件带入；第二至第四部分由 Claude 整理，第五部分为固定指令。

## 一、用户需求

### 1. 项目名称（可选）
【用户填写】

### 2. 目标与使用场景（必填）
【用户填写】谁来用、要解决什么问题、希望实现什么结果。

### 3. 需要的功能（必填）
【用户填写】一条一行，可区分“必须做”和“最好有”。

### 4. 已有技术与资源（必填）
【用户填写】已有代码、技术栈、接口、数据、素材或设备；没有可写“无”，技术未定可写“请 Claude 推荐”。

### 5. 参考项目与界面风格（可选）
【用户填写】项目链接、截图或素材路径，并说明想借鉴的功能、布局或视觉风格。

### 6. 约束与不做的内容（可选）
【用户填写】运行平台、兼容要求、时间、离线要求、不可改动的内容等。

### 7. 完成预期（可选）
【用户填写】最终要拿到什么、怎样使用、怎样判断做到了。

## 二、开发方案【Claude 整理】

### 1. 目标与范围
复述用户目标，列出本次交付内容和范围外事项。区分已确认要求、可调整的默认方案和待确认事项。

### 2. 功能与验收
为每个功能分配 F 编号，为验收标准分配 A 编号；每项必做功能至少对应一条验收标准。

| 功能编号 | 功能与边界 | 优先级 | 验收编号与通过条件 | 验证方式及所需证据 |
|---|---|---|---|---|
| F1 | | 必须 / 最好有 | A1： | |

### 3. 技术与实施
- 根据现有项目提出技术方案、改动模块、接口或数据流；说明新增依赖及理由。
- 按“可运行骨架 → 核心流程 → 完整功能 → 验收交付”拆分任务，每步写明产出和检查方式。
- 只列影响实施的风险、缺失资源和应对方案；性能与兼容要求需有明确环境或指标。

## 三、美术与交互方案【Claude 整理】

有界面的项目必须明确以下内容；无界面项目写明“不涉及用户界面”。

- **页面与操作流程**：主要页面、入口、导航和关键操作，说明用户如何完成核心任务。
- **视觉规范**：参考风格、配色、字体层级、间距、图标、组件与素材来源；沿用已有产品规范。
- **适配与状态**：目标设备和屏幕尺寸，以及加载、空数据、错误、成功、禁用等必要状态。
- **设计确认与验收**：先提交一个关键页面的原型或效果供用户确认，再扩展其他页面；交付时用实际运行的截图或录屏核对布局、视觉一致性和操作流程。

## 四、评审与交付【Claude 整理，用户确认】

Claude 按下列角色分别给出 AI 预审意见。预审检查方案能否开工，成品质量由开发后的实际验证确认。

| 角色 | 检查重点 | 结论与依据 / 整改要求 |
|---|---|---|
| 产品组 | 用户目标、必做功能、范围和优先级是否一致 | 待审 |
| 技术组 | 技术方案、依赖、接口与资源是否可行 | 待审 |
| 美术 / 交互组 | 视觉方向、页面流程、适配和界面验收要求是否明确 | 待审 |
| 开发组 | 任务拆分、改动范围、集成和实施风险是否可控 | 待审 |
| 测试组 | 每项必做功能是否有可复现的通过条件与验证方法 | 待审 |
| 安全组（按需） | 涉及登录、权限或敏感数据时检查安全边界 | 待审 |
| 交付组（按需） | 涉及安装、打包或部署时检查运行环境、交付物与恢复方式 | 待审 |

- **AI 预审结论**：待审 / 通过 / 需补充 / 驳回。
- **阻塞问题**：指出对应功能或方案、影响和需补充的内容；没有则写“无”。
- **用户确认**：待确认，由用户在插件中操作，Claude 不代填确认结果。
- **最终交付物**：列出代码、安装包或可运行产物，以及必要的运行和验证说明。

## 五、固定指令

1. 保留用户需求原文。先检查项目入口、技术配置和相关文件，再补全第二至第四部分；参考资料仅引用实际核实的内容，未能访问的标明“未核实”。
2. 常规实现细节可给出默认方案；会改变目标、核心功能、关键技术路线或权限边界的问题必须交用户确认。未确定技术栈本身不作为驳回理由。
3. 评审只用“通过 / 需补充 / 驳回”；安全和交付不涉及时可写“不适用”并说明原因。美术组对无界面项目说明依据后放行。任一适用角色未通过、或仍有阻塞问题，都不能交给 DSH。
4. 通过预审只表示方案可实施。开发完成后必须逐项验证 A 编号标准；界面还需实际视觉与操作检查。未执行、未覆盖或缺少证据的项标记“未验证”。
5. 需求文档修改后重新评审，用户确认后交给 DSH。DSH 不得擅自删除必做功能、改变设计方向或降低验收标准；实质变更先交用户确认。
