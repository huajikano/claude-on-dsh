# v2.6.1

## 修复

### 已结束的会话在接管列表里仍显示「已在监工」

v2.6.0 的接管列表把「监工里有这一行」当成了「正在监工」。监工的行在完成后不会消失——它要保留 `complete` 状态给概览显示「已达标」和判定依据——于是同一个会话在两处说法相反：

| 位置 | 判据 | 显示 |
|---|---|---|
| 概览 | `phase === 'complete'` | 已达标 · 停止监工 |
| 接管会话 | 行存在即算 | 已在监工 |

`paused` 和 `attention` 有同样的问题；`excluded` 的行被列表过滤，所以没暴露。

改动：

- `supervision-policy.js` 新增 `SUPERVISION_HOLDING_PHASES`、`isHoldingPhase`、`isActivelyMonitored`，作为「是否仍在监工」的唯一定义。
- `supervision.js` 原来自己维护一份 `held` 阶段列表，现在改为引用同一函数，避免两处再次漂移。
- `GET /sessions` 的 `monitored` 改为按 `isActivelyMonitored` 判断，并新增 `supervisionPhase`，把 `complete` / `paused` / `attention` 带给面板。
- 接管列表按阶段给出不同动作：真正在监工显示「已在监工」并禁用；已达标 / 已暂停 / 需要核对显示「重新接管」且可点击，悬停显示具体阶段；从未接管显示「开始监工」。

重新接管会走 `adopt`，清空 `lastTurnKey`，让当前轮次重新判定，符合「已达标但用户想再盯一轮」的预期。

## 验证

- 全量 acceptance 测试：234/234 通过。
- 新增回归用例：
  - 已完成的会话 `monitored=false`、`supervisionPhase='complete'`；
  - 正在监工的会话 `monitored=true`、`supervisionPhase='watching'`；
  - 已暂停的会话 `monitored=false`、`supervisionPhase='paused'`。
- 未实测：真实浏览器里两处状态是否同时刷新；本次验证的是接口字段与面板取值逻辑。
