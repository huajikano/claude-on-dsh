# v2.5.2

## 修复

### 监工不再漏掉会话断开、重连与失败

- 监工新增订阅 `agent/error`、`api-session/status`、`api-session/error`、`api-session/added`、`api-session/removed` 和 `session/disposed`：主会话的运行、失败、Agent 可用性变化与终止都会进入状态机，而不再只依赖 `agent/status` 与 `turn/end`。
- 会话仍被 Host 报告为 `running` 时，终止检查改为退避重试（1s 起，上限 8s），不再丢弃这次触发。
- 会话断开后不再被动等一个可能永远不来的 `api-session/added`：改为主动探测重连，2s 起指数退避（上限 60s），连续 12 次失败才转为「需要核对」，避免单行永久卡死。
- 快照读不到（Agent 已释放、非主会话、缺工作目录、还没有目标）以前是静默 `return`，界面仍显示「等待下轮」；现在分别给出可读原因并进入重试。
- 监工概览在会话断开时显示「DSH 会话已断开，等待重新连接」。
- 全局监工关闭时，会话行不再显示「等待下轮」（会造成「正在监工」的错觉），改为「未在监工」，并在概览顶部说明原因。

### 续跑消息只发下一步

- 续跑消息从「标记 + 空行 + 结论 + 依据段落」精简为 `[Claude 监工] <下一步>`，没有具体下一步时就是 `[Claude 监工] 继续`。
- 保留标记前缀的原因：Session `prompt` 契约没有 `source` 字段，无法给消息打来源，正文前缀是监工区分自己消息与用户手打「继续」的唯一手段。

### 恢复监工按钮点了没反应

- 「恢复监工」不再被全局开关禁用（仅在 `sending` 时禁用）。
- 全局监工关闭时点恢复，会先切到「执行」任务模式再恢复该会话，并提示已切换，而不是留一个无响应的死按钮。
- 概览顶部显示「全局监工当前已关闭（规划/审查模式会关闭它）」，按钮悬停也有同样说明。

### 顶部任务条堆满历史失败

- 已结束的失败任务以前会永久留在顶部任务条，只能点「重试」，反复失败就不断堆积。
- 现在只显示 15 分钟内的失败/中断/取消；每条可单独「移除」，整条可「清除已结束」。
- 新增 `POST /jobs/dismiss`：带 `id` 移除单条，不带 `id` 清空所有已结束任务；运行中的任务拒绝移除。
- 移除会持久化到 `jobs.json`，重启后不再出现。

### 派发报「DSH 会话模式不存在」

- 插件自带配置的默认 `dispatchAgentPreset` 是 `claude`，该预设由 `@norman-else/dsh-claude` 提供；未安装该插件时，每次派发都会失败。
- 现在区分「用户显式选择」与「配置默认值」：配置里的默认预设在本机不存在时，记录一条警告并回退到 DSH 默认预设；用户手动选错仍然报错，保留既有约束。
- 面板加载到真实预设清单后，会清掉快照里本机不存在的旧预设值，避免旧值被重新提交。

## 验证

- 全量 acceptance 测试：214/214 通过。
- 新增回归用例覆盖：忙碌竞态重试、`agent/error` 触发、断连自动探测恢复、断开期间不动作、不可读快照上报、无目标提示、全局关闭标签、续跑消息格式与自身识别、任务移除/清空/运行中拒绝移除、过期失败不显示、预设缺失回退与显式选择仍报错。
- 用真实会话日志（`session-06faf19f`，3 个 turn 全部 `completed`、`goal` 5497 字）做端到端复现：检查从 `checks: 0` 推进到 `checks: 1`，发出消息为 `[Claude 监工] 继续` 且被正确识别为监工自身消息；模拟断连后进入 `retrying`，探测可读后自动恢复且不重复处理。
- 未实测：真实浏览器断网环境下的端到端表现；本次验证的是事件处理与状态机转换。
