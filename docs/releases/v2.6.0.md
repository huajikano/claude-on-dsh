# v2.6.0

## 新增

### 睡眠托管（无人值守）

「监工设置」新增 `sleepMode` 开关。打开后由监工接手主会话的完成、续跑和中断处理，不等待用户确认，也不要求面板保持打开。

- 强制使用本机 CLI 监工，不使用需要人工回填的 Desktop 引擎；引擎下拉在开启时锁定为 CLI。
- 强制开启全局监工，并在启用时立即检查已绑定的未结束会话，不必等下一次 `turn/end`。
- 关闭旧的交互式验收询问（`autoPrompt` / `autoAcceptance`），夜间不会卡在等待选择。
- 必须设置 `dailyBudgetUsd > 0` 才能开启；面板、`POST /settings`、`POST /task-modes` 三处都会校验，保存的旧配置若为 0 则在启动时自动退出睡眠托管并记录警告。
- 仍受每日预算、`maxRetries`、`maxNoProgress`、`maxRounds` 约束；任一上限触发后转为暂停或「需要核对」。
- 切换普通任务模式（规划/审查）不会悄悄关掉睡眠托管。
- `GET /supervision` 返回 `sleepMode`，概览顶部显示「睡眠托管已接管」。

### 任务书验收标准（A1、A2…）进入报告契约

此前验收标准编号只活在提示词文本里，`JUDGE_SCHEMA` 没有承载字段，报告里也没有逐项章节，于是可以 overall=pass 而所有标准从未被验证。

- `JUDGE_SCHEMA` 增加 `criteria: [{ id, conclusion, evidenceIds, note }]`。
- 校验器要求每个编号都有结论；pass/fail 必须引用证据；缺失编号报 `missing criterion A3`。
- 报告输出 `criteria` 章节，未通过的编号写入 `missing: criterion-unverified:A3`。
- Markdown 报告新增「任务书验收标准」逐项表格。
- `contract.js` 同步校验报告里的 criteria 结构。

### 失败诊断

- CLI 非零退出时，错误对象带 `details`：`exitCode`、`executable`、`argv`（长值截断）、`stderr`（8 KB）、`stdout`（4 KB）、`durationMs`。
- 同时追加一行到 `$DSH_HOME/claude-on-dsh/logs/cli-YYYY-MM-DD.log`，保留完整输出。
- 面板错误卡片可展开「详细的失败信息」，任务记录也会持久化 `details`。
- `endpoint()` 把 `details` 透传给前端。

## 修复

### 主题外泄到 DSH 宿主

v2.5.2 起 `panel.css` 把 `color-scheme` 和 `--cc-*` token 定义在 `:root` 上。`:root` 是 `<html>`，`color-scheme` 打在那里会改变整个宿主页面的渲染（滚动条、表单控件、宿主自己样式表里的 `light-dark()`）。

- token 块改为 `.cc-panel, .cc-reviewBadge, .cc-modalBackdrop`；后两个渲染在聊天消息区，必须单列。
- 两条 `:root` 的 `color-scheme` 规则删除，改为只作用于上述三个类。
- `@supports` 兜底块同步改掉，不再触碰 `:root`。
- 顺带修掉 `--cc-paper: var(--dsh-claude-card, var(--cc-paper))` 这类自引用 fallback（按规范属 computed-value 循环，会整条失效）。
- 增加 `data-theme="dark"` / `.dark` 兼容，以及不支持 `light-dark()` 时的亮色兜底。

### 监工

- **提示词尺寸上限**：模型输入硬上限 60,000 字符。长对话、工具参数与输出、Git 文件列表都做压缩，保留首尾并标注已截断。此前单次可达 150–450 KB，每轮结束重复发送。
- **按会话并行**：`enqueue` 从一条全局串行链改为按 `sessionId` 分队列。同一会话仍串行（防重复发送），不同会话可并行，一个慢项目不再阻塞其它项目。
- **预算闸门说明修正**：`cli` 引擎本身会走 `runClaudeFor` 并在 SDK / CLI 之间选择，两者都记同一本账，因此闸门按 `cli` 判断覆盖了两条路径；`desktop` 不经这本账所以跳过。

### 验收

- **`allowedPaths` 路径穿越**：先做 posix 归一化再逐段比较，`workspace/../etc/x` 不再被判为工作区内；`**/` 翻成 `(?:.*/)?`，`**/*.js` 现在能匹配根目录文件；大小写折叠只在 win32 生效。
- **`scopeChecker` 不再抽样**：此前只检查前 30 个改动文件，note 却宣称「全部位于允许路径内」。现在全量检查，数字是真的。
- **报告原子写**：`writeReports` 改为 tmp + rename，崩溃不再留下半截 JSON。
- **回写验收意见不再提权**：`review.js` 曾为发一条文本消息把会话设成 `danger-full-access`，该行为已删除。
- **验收提示词 git 段**：读取的字段从 `facts.git.status`（不存在）改为 `statusOutput`，此前该段恒为空。
- **验收提示词去重**：移除了重复的「本次新增要求」一行。

### 面板

- **CSS 覆盖检查可用**：`check-panel-coverage.mjs` 此前把路径写死成不存在的 `D:/XiangMu/claude-on-dsh-2.1.4/`，且扫描范围包含内联 CSS，逻辑恒真。现在改为相对路径、剔除内联样式区、识别 `${}` 模板前缀与组合类，缺失即退出码 1。
- **`npm test` 接入闸门**：先跑覆盖检查，再校验 `panel.css` 与 `client.js` 内联内容同步。
- **重复提交**：开始首问、Desktop 流程、选择目录、复制交接书、继续 Desktop 回复、归档会话都加了本地 busy 锁。此前 `disabled` 依赖 `running`，而 `running` 要等 `POST /jobs` 返回，双击能起两个 Claude 作业。
- **`.cc-modal` 缺少定位上下文**：关闭按钮是 `position:absolute`，而 `.cc-modal` 没有 `position:relative`，按钮会跑到视口角落。
- **520px 窄屏规则**：`@container` 里的 `.cc-panel` 规则对容器自身无效，改为 `@media`。
- **补齐缺失样式**：`cc-monitorReason`、`cc-backgroundJobsActions`。
